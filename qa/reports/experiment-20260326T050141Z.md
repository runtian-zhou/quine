## Analysis

Two distinct bug patterns emerged:

### Bug 1: Multi-tool turns produce empty responses (Cases 2, 5, 8, 12)
When the LLM uses 2+ tools in a turn, the `run` command frequently shows no text output. The tools execute successfully (case 2 mentions "completed both operations" suggesting partial text), but the full response is lost. This could be:
- The `text_before` fix from feature 025 not yet implemented — text emitted before tool calls isn't flushed to the client
- The whitespace trim fix being too aggressive — discarding responses that are mostly whitespace
- A race in the one-shot runner between TextComplete/TurnComplete and response collection

### Bug 2: Permission checker blocks pipe commands (Case 10)
Piped bash commands score 0.4 risk even when individual commands are safe (`seq`, `tail`). In non-interactive one-shot mode, RequiresConfirmation hangs forever. The permission checker should either whitelist safe pipe combinations or the one-shot runner should auto-deny (with error) rather than hang.
