## Failures

### Case 1: bash_expr — FAIL
- **Tools**: bash
- **Message**: "Use bash to run: expr 17 + 25. Return the exact number."
- **Expected**: stdout contains `42`
- **Stdout**: `interaction needed: Tool 'bash' with args '{"command":"expr 17 + 25"}' scored 0.3 risk: unrecognized command`
- **Root cause**: **Permission checker** — `expr` is not in the safe command whitelist. It's a read-only arithmetic utility and should be whitelisted. Additionally, the unanswered permission prompt caused the daemon's core channel to close, crashing subsequent requests until restart.

### Case 6: plan_with_deps — FAIL
- **Tools**: plan
- **Message**: "Use the plan tool to create a plan titled 'Deploy Pipeline' with 3 actions..."
- **Expected**: stdout contains plan_id and "build" as ready action
- **Stdout**: "Let me create the plan... I need to include all the required fields..."
- **Root cause**: **LLM model behavior** — the local qwen model struggled with the plan tool's complex JSON schema (nested arrays of objects with dependencies). It kept retrying without successfully forming the tool call. Not a code bug.

### Case 9: bash_pipe_3way — FAIL
- **Tools**: bash
- **Message**: 'Use bash to run: echo -e "cherry\\napple\\nbanana" | sort | head -1'
- **Expected**: stdout contains `apple`
- **Stdout**: empty (only session line)
- **Root cause**: **LLM model behavior** — the tool call likely succeeded (all three pipe segments are whitelisted) but the model produced no text response afterward. Same pattern as prior experiment runs.

## New Findings

### Bug: Unanswered permission prompt crashes daemon
When a permission check triggers `interaction_needed` in non-interactive mode, the core engine blocks on `input.recv()` indefinitely. When the CLI disconnects, the core channel is left in a broken state. **All subsequent `create_session` calls fail** with "core channel closed" until the daemon is restarted. This is a new finding — the daemon should recover from unanswered interactions rather than corrupting the core channel.

### Missing from whitelist: `expr`
`expr` is a standard Unix arithmetic/string utility with no side effects. Should be added to the safe command list alongside `seq`, `rev`, etc.
