## Analysis

Both previously failing tests now pass after the fix to `convert_messages` in `crates/quine-llm/src/anthropic.rs`.

**Root cause (multi_tool_chain):** When the LLM made multiple parallel tool calls, each tool result was pushed as a separate `Message` with `Role::Tool`. The `convert_messages` function converted each into a separate Anthropic API message with role `"user"`, producing consecutive user messages. The Anthropic Messages API requires strict alternating user/assistant roles and rejected these with HTTP 400.

**Root cause (bash_exit_code):** The `exit 42` command triggered a permission prompt (scored 0.3 risk as "unrecognized command"), which caused the first attempt to hang/exit without producing output. On subsequent attempts, the daemon had crashed due to the hung interaction, producing the "core channel closed" error. The underlying multi_tool_chain batching fix prevents the cascading API failures that corrupted the session state.

**Fix applied:** `convert_messages` now merges consecutive `Role::Tool` messages into a single `"user"` message with multiple `tool_result` content blocks, matching the Anthropic API's expected format.

**Note:** The `bash_exit_code` test requires an interaction approval step (permission prompt for `exit 42` as an unrecognized command). This was handled by using `--json` mode to capture the session ID, then `quine respond` to approve the permission. A future improvement could add an `--auto-approve` flag for QA/CI use.
