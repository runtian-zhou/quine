# 053 Session Compact Memory Summary in CLI and TUI — Implementation Plan

Short summary: Hook the CLI and TUI session-inspection surfaces up to compact session memory so operators can see the current session summary generated by compaction without leaving the existing chat and context flows.

## Open Questions

- None. This plan stays scoped to surfacing existing compact-memory session summaries in the existing CLI and TUI session views without introducing a new memory-management workflow.

## Agreement Status

agreed — Reviewed against the QA plan. Both docs align on an additive `compact_memory_summary_markdown: Option<String>` field on the harness session-context snapshot, bounded CLI/TUI rendering, and a deterministic seeded-session QA path for live daemon validation.

## Proposed Design

- Build on the compact-memory and session-context structures that already exist today:
  - `SessionMemoryState` in `crates/quine-core/src/memory/session.rs` already tracks compacted summaries and exposes summary text through the session memory snapshot path.
  - `SessionMemoryCompactionSnapshot` in `crates/quine-core/src/compaction.rs` already has the fields needed to describe the current compacted summary and related metadata.
  - `session_context_from_checkpoint` in `crates/quine-harness/src/storage.rs` already translates persisted core session state into the operator-facing `SessionContext` snapshot returned by harness inspection flows.
  - `SessionContextSnapshot` and its renderer in `crates/quine-cli/src/context_debug.rs` already display optional diagnostic sections in CLI output.
  - the TUI in `crates/quine-cli/src/tui/app.rs` already fetches and renders session context details in a dedicated panel.
- Prefer extending the existing session-context snapshot instead of creating a new RPC or a separate memory-debug command.
- Surface only the operator-meaningful compact-memory state needed by this feature:
  - whether a compact-memory summary exists
  - the current summary text itself
- Use a single additive field name throughout the boundary:
  - add `compact_memory_summary_markdown: Option<String>` to `crates/quine-harness/src/storage.rs` `SessionContextSnapshot`
  - derive it from `PersistedSession.memory_state.compaction.summary_markdown` for restored sessions
  - derive it from the live session memory snapshot for active sessions
- Keep the compact-memory summary additive and backward compatible:
  - harness session-context responses should grow by adding optional fields
  - CLI and TUI should render the summary when present and remain unchanged when no compacted summary exists yet
- Reuse the existing context inspection entry points rather than inventing a second UI path:
  - the CLI `/context` flow should include the compact-memory summary in its rendered session snapshot
  - any non-interactive or JSON context output already driven by `SessionContextSnapshot` should carry the same additive field
  - the TUI session/context pane should display the summary in a readable bounded section alongside existing diagnostics
- Keep formatting conservative:
  - preserve the original summary text generated by compaction rather than re-summarizing it in the CLI
  - truncate or wrap only according to the existing renderer and TUI layout rules so the UI remains stable
- Keep write-side behavior out of scope:
  - do not change when compaction runs
  - do not change summary generation logic except where a small refactor is required to expose existing data cleanly through session context

## File-by-File Changes

- `crates/quine-core/src/memory/session.rs`
  - Reuse the existing `SessionMemorySnapshot.compaction: Option<SessionMemoryCompactionSnapshot>` data and `summary_markdown` field as the canonical source.
  - If needed, add only a tiny helper that returns `Option<&str>` or `Option<String>` for the current compact-memory summary so session-context assembly does not duplicate extraction logic.
- `crates/quine-core/src/compaction.rs`
  - Reuse the existing `SessionMemoryCompactionSnapshot.summary_markdown` field directly.
  - Do not expand the compaction snapshot shape unless implementation discovers a missing accessor; the feature only needs the already-generated markdown summary text.
- `crates/quine-harness/src/storage.rs`
  - Extend `SessionContextSnapshot` with `compact_memory_summary_markdown: Option<String>`.
  - Populate it in `snapshot_from_persisted()` from `session.memory_state.as_ref().and_then(|state| state.compaction.as_ref()).map(|compaction| compaction.summary_markdown.clone())`.
- `crates/quine-harness/src/local.rs`
  - Ensure the live `get_session_context()` path populates the same `compact_memory_summary_markdown: Option<String>` field from the in-memory session context or memory snapshot, not just from checkpoint restoration.
  - Keep the live and restored derivations text-identical so `/context` and TUI inspection produce the same summary regardless of session source.
- `crates/quine-cli/src/context_debug.rs`
  - Extend the CLI-side deserialization mirror of `SessionContextSnapshot` with `compact_memory_summary_markdown: Option<String>`.
  - Update the renderer so `/context` or equivalent CLI session-context views show a clearly labeled `Session Summary` section when present.
  - Preserve JSON serialization compatibility by adding the optional field without renaming any existing fields.
- `crates/quine-cli/src/chat.rs`
  - Reuse the existing `/context` command path so interactive CLI users can inspect the compact-memory summary without a new command.
- `crates/quine-cli/src/tui/app.rs`
  - Add the compact-memory summary to the existing context/session details panel shown in the TUI.
  - Render it under a `Session Summary` label, using the current wrapping and clipping rules already used by the TUI details view so long summaries stay bounded.
- Tests in `quine-core`, `quine-harness`, and `quine-cli`
  - Add focused coverage that a session context containing a compacted summary serializes through the harness boundary and renders in both CLI and TUI snapshot layers.

## Validation Plan

- Unit tests in `quine-core` verifying the session-context snapshot includes compact-memory summary data when compaction state exists and omits it cleanly otherwise.
- Harness tests around `get_session_context()` and checkpoint restoration verifying the same summary appears for live and restored sessions.
- A deterministic seeded-session harness test helper or fixture that injects `compact_memory_summary_markdown` into session state for daemon-backed QA, so QA does not depend on compaction timing or token thresholds.
- CLI snapshot or renderer tests in `context_debug.rs` verifying:
  - the summary section is rendered when present
  - no empty section is rendered when absent
  - JSON snapshot serialization includes the additive field
- TUI-focused tests at the state/render helper level verifying the context panel includes the summary text when session context contains compact-memory data.
- Workspace validation from the repository root:
  - `cargo test -p quine-core memory:: -- --nocapture`
  - `cargo test -p quine-harness get_session_context -- --nocapture`
  - `cargo test -p quine-cli context -- --nocapture`
  - `cargo build`
  - `cargo test`
  - `cargo clippy --all-targets -- -D warnings`
  - `cargo fmt --all -- --check`

## QA Feedback

- The QA plan is correct to require a daemon-backed scenario, but it should rely on a deterministic seeded-session setup rather than hoping ordinary chat volume triggers compaction.
- Assert the exact additive field name `compact_memory_summary_markdown` in CLI-side JSON serialization tests and any harness snapshot tests.
- The TUI check should target the existing session/context details formatting helper if one exists; if not, add a narrow helper-level test rather than a brittle full terminal snapshot.
- The daemon-backed scenario should start from a fixture-backed or test-only preseeded session/checkpoint whose compact-memory summary text is known ahead of time, then verify `/context` shows that exact text.
